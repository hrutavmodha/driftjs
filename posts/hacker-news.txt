Title: Show HN: DriftJS - Ultra-Fast, Register-Based Bytecode Virtual Machine UI Framework

Hi HN,

I'm sharing an experimental frontend framework prototype called DriftJS. Instead of using a Virtual DOM or heavily relying on ahead-of-time reactivity compilation, DriftJS explores compiling templates into compact binary-serializable bytecode streams and executing them in the browser via a lightweight 256-register Virtual Machine (the `DriftClientVM`).

Key architectural details:
- Register-Based VM: We use exactly 256 fast virtual registers for DOM elements and evaluated values, keeping memory allocation extremely low.
- 15-Opcode ISA: A minimal instruction set (e.g. 0x01 CREATE_ELEMENT, 0x05 SET_ATTR, 0x0E REACTIVE_FOR) drives the DOM updates directly.
- Keyed LIS Reconciliation: Uses the Longest Increasing Subsequence algorithm to minimize DOM operations during loop updates.
- 100% CSP Compliant: Built-in Acorn AST interpreter safely evaluates JS expressions without eval() or new Function().

The performance is highly promising. In the `js-framework-benchmark` suite against React 19, DriftJS is:
- 10.8x FASTER on "Swap rows (1k)"
- 3.05x FASTER on "Clear 1,000 rows"
- Uses ~1.8x less memory during Run-Clear.
- 5.75x smaller uncompressed bundle size.

DriftJS is very early (no component composition, SSR, or stores yet). We're sharing it now to see if this 15-opcode, register-based VM approach is an interesting direction for UI frameworks, and to invite compiler engineers to collaborate.

Repo: https://github.com/hrutavmodha/driftjs

Would love to hear your thoughts on the VM architecture and bytecode approach!
